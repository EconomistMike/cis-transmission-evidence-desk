## Non-negotiable implementation boundary

- Add this as a new chart at the top of **Latest evidence**; retain the detailed observation table below it.
- Do not alter `policy_chart.original_row`, `policy_chart.findings`, `D.chart_columns`, the supplied workbook, or any Workbook comparison renderer/data.

- Every displayed value must retain its unit, evidence date, price basis (for cost), scope, source ID and pinpoint in its detail view.
- `NE` means **not established in this snapshot**, not zero. `ND` means **the requested category is not source-defined**, so no count is made.

- Cost/km is shown only where numerator and denominator have a defensible common project boundary; otherwise it is `NE — incompatible scope`.

## Decisions required before implementation

1. **Column labels.** Keep the workbook’s visual order, but use explicit latest-evidence labels: `Scope / stage`, `Delivery milestone`, `Cost evidence`, `Capacity measure`, `Route length`, `Cost / route km`, `Circuits`, `Lines / links`, `Alternative routes`, `Synchronous condensers`, `Hubs / stations`, `Transformers`, `Feeder / spur length`, `Notes / sources`. This preserves comparison without implying that the new chart uses workbook inputs.
2. **Alternative routes.** No source supplies a comparable count for any family. Recommended treatment: show `ND — no source-defined count` in every latest-evidence row. Do not copy workbook zeros or infer a number from RIT-T options.
3. **Hubs.** “Hub” is not consistent across projects. Recommended treatment: count only assets explicitly called hubs; list named switchyards/terminal/switching stations without converting them to hubs.
4. **Circuits versus lines.** Use source terminology and boundary. A double-circuit line may be `2 circuits; 1 line`; do not multiply across corridor sections unless the source itself supplies a whole-scope count. For CWO’s four circuits, label the value `derived: 2 lines × 2 circuits`.
5. **Transformer and syncon display.** Recommended treatment: `4 × 1,500 MVA` rather than `6,000 MVA`. This intentionally differs from the workbook’s summed-MVA cells and follows the instruction not to sum units.
6. **Cost selection.** Recommended treatment: show multiple cost observations only when they represent materially different authoritative perspectives (for example, HumeLink’s planner estimate and AER allowance), never as an unexplained total. No price-basis conversion is authorised.
7. **Cost/km.** Recommended treatment: calculate only CWO Main (`$5,526.1m / 90 km = $61.40m/km`), HumeLink planner (`$4,892m / 365 km = $13.40m/km`), and PEC NSW (`$3,628m / 700 km = $5.18m/km`). These are project-capex-per-route-km indicators, not line-construction unit rates. All other rows remain unavailable because cost, length, or common scope is missing. If “cost/km” is intended to mean line-only construction cost, suppress the column entirely because none of these numerators is line-only.
8. **HTP post-cut-off web records.** The 110 km EnergyCo records are dated `2026-09` in the pack, later than the 4 September cutoff, although they were added as bounded corrections. Recommended treatment: do not use them in the new “through 4 September” chart unless the recorded capture date is corrected or an in-cutoff source is established. The draft therefore marks HTP route length and cost/km pending this decision.
9. **Marinus cost boundary.** The `$7,570m` figure is Project Marinus (Link plus NWTD), not Link-only. Recommended treatment: show it once on a Project Marinus umbrella row; do not duplicate or allocate it to Stage 1/2. Show `$2,485m` only as Stage 2 Option 2A, not an amount additive to `$7,570m`.
10. **VNI cost boundary.** Show `$7,600m` once on an integrated VNI West row. Do not repeat it in NSW and Victoria rows, split it in half, or calculate state cost/km.
11. **PEC scope.** Keep whole-project route (`~900 km`), NSW route (`700 km`), Stage 1 (`160 km`) and Stage 2 (`540 km`) as separate boundaries. The `$3,628m` cost belongs only to Transgrid’s NSW forecast and must not appear as whole-project capex.
12. **SRS option choice.** Recommended treatment: represent PADR Option 6 in three rows (combined, Stage 1, Stage 2), while retaining AEMO’s separate 2025-dollar modelled options in details. Do not combine the nominal PADR amount with the older 114 km route or use it for cost/km.

## Unsupported cells and scope traps by column

- **Cost:** CWO family total, New England NIP, Link-only Marinus, whole PEC, NSW-only/Victoria-only VNI, and standalone WRL are not established. HTP’s cost is broader than the 110 km line. Do not fill any of these from workbook values.
- **Capacity:** no common definition exists across rows. The chart must label transfer uplift, REZ hosting, declared intended capacity, renewable capacity harnessed, and line capability distinctly.
- **Route length:** HTP is cutoff-pending; New England and VNI use indicative/not-final corridor measures; HumeLink’s metric type is unstated; Marinus gives subsea and underground lengths separately; PEC has overlapping whole/state/stage measures.
- **Cost/km:** unavailable whenever the cost or length is unavailable, or their boundaries differ. Never carry through workbook formulas.
- **Alternative routes:** unsupported as a comparable quantitative field for all projects.
- **Syncons:** absence from a scope list is not zero. CWO has an unresolved 250 versus 240 MVA per-unit discrepancy. PEC has source-stated units that must not be silently summed.
- **Hubs:** zeros are generally unsupported. Use only explicit “hub” terminology; switching stations and terminal stations remain named assets.
- **Transformers:** do not show summed MVA. Preserve unit count, unit rating, voltage and site. PEC has several transformer types and no defensible project total.
- **Feeder lines:** zeros are unsupported. CWO has 150/166 km alternatives; PEC has a 22 km spur whose feeder classification is unresolved; other rows are not established.
